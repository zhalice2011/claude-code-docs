# 启动性能采集

启动性能采集用于定位 CodeBuddy 启动缓慢问题。使用 `--startup-prof-md` 后，CodeBuddy 会在启动就绪时生成 Markdown 和 JSON 报告。

## 使用

诊断选项需放在其他参数之前：

sh
```
codebuddy --startup-prof-md
```
也可以同时执行一次任务：

sh
```
codebuddy --startup-prof-md -p "say hi"
```
如需指定报告输出目录：

sh
```
codebuddy --startup-prof-md --startup-prof-dir ./profiles
```

| 参数 | 说明 |
| --- | --- |
| `--startup-prof` | 仅生成 JSON 报告 |
| `--startup-prof-md` | 同时生成 Markdown 和 JSON 报告 |
| `--startup-prof-dir <directory>` | 指定报告输出目录，默认为当前工作目录 |
| `--startup-prof-name <name>` | 指定报告文件名；扩展名会自动补全，已有文件不会被覆盖 |

通常只需使用 `--startup-prof-md`。交互界面启动就绪后会自动生成报告，当前会话仍可继续使用，无需退出。报告位置会输出到错误流，不影响标准输出的原有格式。

## 报告内容

报告包含：

- 运行环境与版本摘要
- 启动总耗时和关键里程碑
- 耗时较长的阶段及完整时间线
- 启动完成时的资源使用情况

采集不会主动记录提示词、请求正文、凭证、完整环境变量或配置内容。部分阶段可能并行或重叠，因此不要将各阶段耗时直接相加作为总启动时间。

## 采集边界与对比建议

CodeBuddy 会根据运行方式自动判断启动完成时机：单次任务统计到首次请求发起前，交互模式统计到界面就绪，服务模式统计到服务可用。

若进程在启动完成前正常退出，仍可能生成部分报告；强制终止或运行时崩溃时无法保证报告生成。采集超过 60 秒仍未完成时会先生成当前报告，进程继续运行。

比较优化前后的结果时，请保持运行环境、版本、运行方式、参数和配置一致，并分别进行多次冷启动与热启动采样。采集仅在显式开启时运行，不会上报网络数据，也不会改变正常启动流程。
